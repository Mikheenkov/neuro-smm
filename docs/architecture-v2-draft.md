## 0. Главные решения

1. **Оркестратор — обычный детерминированный Python-демон, а не LLM-агент.** Он принимает посты, держит буфер, классифицирует ссылки, валидирует результат, публикует, ведёт учёт и пишет отчёты. LLM работает только там, где нужно понимание текста: анализ поста, адаптация под сеть, судья, перенос правок, раскадровка рилса. Каждый LLM-шаг — короткий отдельный запуск `claude -p --agent <имя>` со строгой JSON-схемой ответа.
2. **«Понимает, как автор» обеспечивают четыре вещи вместе:**
   - один анализ поста, который получают все сети;
   - скилл голоса автора и 10–20 эталонных пар;
   - скилл под каждую сеть;
   - петля исправлений: правки автора сохраняются как примеры и раз в неделю сводятся в правила, но только с его одобрения.
3. **Ссылки модель никогда не пишет сама.** Код заменяет каждую ссылку плейсхолдером `L1…Ln` и по таблице политик решает для каждой сети, что с ней делать. Модель выбирает только формулировку вокруг ссылки. Реальный URL подставляет рендерер, а валидатор отклоняет любой URL не из манифеста. Статус блокировки домена определяет только таблица `domain_policy`, знания модели здесь не используются.
4. **Публикация идёт только через официальные API**: MAX Bot API, VK API, FB Pages API, Threads API, IG API, Telegram Bot API. Браузер на сервере (Playwright плюс noVNC для входа автора) нужен ровно в двух местах:
   - VK-посты, если devsupport не выдаст пользовательский токен с правом `wall`;
   - VK Клипы в фазе 3, потому что официального API для клипов нет.
5. **Тайминг.** Пост появился в момент T. Около T+3 мин готовы черновики, и автор получает предпросмотр. В T+60 код проверяет, что пост не удалён, и берёт его актуальную версию. После этого идёт публикация в порядке Threads → FB → MAX → VK → IG, затем отчёт со ссылками.
6. **Первыми запускаем MAX и Threads.** MAX — главная цель для российской аудитории, на нём проверяется вся логика замены ссылок, API чистый и с HTML. Threads подключается быстрее всех: роли Tester хватает. Он сразу проверяет весь конвейер в «международном» режиме и нужен FB как хаб ссылок. VK зависит от ответа devsupport, поэтому письмо туда отправляем в первый же день.
7. **FB Page по умолчанию публикуется без внешних ссылок.** Вместо них строка «Ссылки из поста — в Threads: <permalink>»: по справке Meta ссылки на сервисы Meta не расходуют лимит. Два «ссылочных» поста в месяц тратим только на важные собственные ссылки, и код ведёт их бюджет.
8. **MAX-канал нужно сделать публичным.** У постов приватного канала `Message.url = null`: без этого не будет ни ссылок в отчёте, ни перекрёстных ссылок.
9. **LLM можно заменить на другого вендора.** Скиллы лежат в открытом формате Agent Skills, доменные инструменты — в отдельном stdio MCP-сервере, JSON-схемы написаны в общем строгом подмножестве. Над всем этим тонкий адаптер `run_agent()` с тремя реализациями: `claude -p`, `codex exec`, OpenAI Responses API. Почти весь контекст передаётся во входном JSON, так что инструменты для модели необязательны.
10. **Подписка Claude.** Без `--bare`: этот режим не читает OAuth-токен. Версия Claude Code закреплена, `ANTHROPIC_API_KEY` в окружении демона отсутствует. Расход — примерно 6–9 запусков на пост.
11. **Рилсы (фаза 3).** Мастер-ролик 1080×1920 H.264 собирается так: Claude пишет раскадровку, голос даёт TTS с таймингами, ИИ-иллюстрации идут без текста, а русский текст рендерит код (Remotion). Ролик ≤60 с и ≤45 МБ подходит без перемонтажа для видеопоста в TG, IG Reels, FB Reels, MAX, Threads и VK Клипов. Перед публикацией автор обязательно видит превью.
12. **Реклама, VPN и обход блокировок отсекаются кодом** до LLM и ещё раз после него. LLM-подозрение на рекламу без явной маркировки останавливает пост и отправляет автору вопрос.

## 1. Контекст и принципы

- **Источник** — Telegram-канал автора (судя по существующему скиллу `nikita-telegram-posts`, это @mikheenkovnews): AI-инструменты, бизнес, менеджмент. Около одного поста в день: текст, картинка с текстом, иногда видео с текстом.
- **Целевые площадки:** MAX (сейчас приватный канал, автор самозанятый), VK, Facebook Page, Threads, позже Instagram, ещё позже рилсы.
- **Где что работает.** Автор в Португалии, сервер в Испании. Российская аудитория MAX и VK не может открыть Telegram (78–95% аномалий по OONI), сервисы Meta, X, LinkedIn, YouTube. Часть мобильной аудитории сидит на «белых списках». Зарубежная аудитория Threads и FB, наоборот, спокойно открывает Telegram, но не будет пользоваться MAX и VK.
- **Принципы:**
  1. LLM пишет текст, код принимает решения о ссылках, правах, бюджете и публикации.
  2. Каждый LLM-запуск короткий и без состояния: на входе JSON, на выходе JSON по схеме.
  3. Публикация всегда идемпотентна.
  4. Сбой в одной сети не блокирует остальные.
  5. Всё, что меняется (лимиты, статусы доменов, модели), хранится в конфиге или БД, а не в коде.
  6. Правило Rule of Two: агент, который читает чужие страницы, не имеет инструментов, меняющих состояние, а публикует только код.

## 2. Общая архитектура

```
Telegram-канал автора
   │ channel_post / edited_channel_post (бот-админ, long polling через локальный telegram-bot-api)
   ▼
┌──────────────────────── smm-daemon (Python 3.12, asyncio) ────────────────────────┐
│ Ingest ─► SQLite(WAL) ◄─ Scheduler/Jobs ─► Pipeline workers (конкурентность 1–2)  │
│   │                                     │                                         │
│   │                     ┌───────────────┼───────────────────────────┐             │
│   │                     ▼               ▼                           ▼             │
│   │             LinkPolicy engine   LLM Runner (adapter)       Publishers (код)   │
│   │             (нормализация,      ├ ClaudeCliRunner          ├ max_api          │
│   │              классы, решения)   ├ CodexExecRunner          ├ vk_api / vk_browser
│   │                                 └ OpenAIResponsesRunner    ├ fb_pages         │
│   │                                    │ (claude -p --agent …) ├ threads          │
│   │                                    ▼                       ├ instagram        │
│   │                              stdio MCP «smm» (read-only)   └ telegram         │
│   ▼                                                                               │
│ Reporter (TG: превью, отчёты, кнопки)   Health/Tokens/PolicyUpdater (cron)        │
└───────────────────────────────────────────────────────────────────────────────────┘
   │                         │                           │
 nginx (TLS, публичные      Playwright-браузер +        Remotion-рендерер (фаза 3)
 медиа-URL с TTL)           noVNC (вход автора, VK)
```

**Инфраструктура.** Один VPS в Испании: 2 vCPU и 4 ГБ RAM для фаз 1–2, 4 vCPU и 8 ГБ с фазы 3. Docker Compose со следующими сервисами:

- `smm-daemon` — в том же контейнере установлен Claude Code CLI с закреплённой версией и MCP-сервер, который CLI запускает как stdio-подпроцесс;
- `tg-bot-api` — локальный Telegram Bot API server: скачивание файлов больше 20 МБ и загрузка до 2000 МБ; для него нужны api_id и api_hash сервера, это не userbot;
- `nginx` — домен с Let's Encrypt; раздаёт медиа по случайным путям с TTL для IG и Threads и, при необходимости, для FB;
- `browser` — Chromium, Playwright и noVNC; поднимается по требованию;
- `renderer` — Remotion, с фазы 3;
- `backup` — cron.

**Сеть.** До запуска нужно проверить с IP дата-центра в Испании, что VK API и MAX API отвечают. С апреля 2026 российские сервисы режут зарубежные IP и IP хостингов. Если IP окажется заблокирован, исходящие вызовы к `api.vk.ru` и `platform-api2.max.ru` пойдут через маленький российский VPS-ретранслятор. Это обычная серверная инфраструктура для доступа к российским API, к обходу блокировок для пользователей она отношения не имеет.

## 3. Конвейер по стадиям

### 3.1 Ingest

- Бот — администратор канала. Право `can_post_messages` нужно только для фазы 3, когда бот публикует видео. Используется long polling `getUpdates` с `allowed_updates=["channel_post","edited_channel_post","message","callback_query"]` через локальный `tg-bot-api`.
- **Альбомы.** Сообщения с одинаковым `media_group_id` собираются в окне 3 с в один `post`. Подпись обычно у первого элемента, правки приходят по каждому элементу отдельно.
- **Сохраняется:**
  - `text` или `caption`;
  - полные `entities` или `caption_entities` (`url`, `text_link`, `mention`, `text_mention`, `bold`, `italic`, `underline`, `strikethrough`, `spoiler`, `code`, `pre`, `blockquote`, `expandable_blockquote`, `custom_emoji`);
  - медиа (`file_id`, `file_unique_id`, размеры, длительность);
  - `forward_origin`, `has_protected_content`.
- **Сразу отсеиваются:**
  - служебные сообщения;
  - опросы, стикеры, голосовые, платные медиа (`paid_media`);
  - пересылки из чужих каналов (по умолчанию пропуск, см. вопросы);
  - сообщения, отправленные самим ботом, по таблице `bot_sent_messages`. Это защита от петли в фазе 3: получает ли бот `channel_post` о собственных сообщениях — **[проверить]**.
- **Rich Messages (Bot API 10.1–10.3, 06–08.2026)** — посты из нового редактора могут прийти в новом формате. Если ingest не распознал тип сообщения, пост получает статус `held` и автору уходит вопрос. **[проверить]**, как такие посты приходят в `channel_post`.
- **Медиа** скачиваются сразу через `getFile` локального сервера (без лимита 20 МБ) в `data/media/<post_id>/`, считается sha256.
- **Нормализация в IR (внутреннее представление).** Это Markdown-подмножество с плейсхолдерами ссылок:
  - `**жирный**`, `_курсив_`, `__подчёркнутый__`, `~~зачёркнутый~~`, `` `код` ``, `> цитата`;
  - ссылки: `[анкор](L1)`, голый URL превращается в `(L2)`;
  - `custom_emoji` заменяется на запасной символ, который уже есть в тексте;
  - `spoiler` становится обычным текстом;
  - `mention @x` превращается в `{{M1}}`.

### 3.2 Буфер на 1 час и предварительная адаптация

- `publish_at = first_seen_at + 60 мин`. Если правка пришла позже T+55, дедлайн сдвигается до `last_edit_at + 5 мин`, но не позже T+90.
- **Предпросмотр** (включён по умолчанию первые 3–4 недели, дальше флаг). Около T+2 запускаются анализ и адаптация. Около T+5 автору в личку приходят черновики по сетям с кнопками:
  - «Не публиковать в X»;
  - «Стоп всё»;
  - «Опубликовать сейчас»;
  - «Исправить» — автор отвечает своим текстом, текст проходит валидаторы и сохраняется как пример исправления.
- **Правка во время буфера** (`edited_channel_post`). Создаётся новая `post_version`, черновики помечаются устаревшими. Через 3 минуты после последней правки (debounce) срабатывает пересчёт:
  - мелкая правка — опечатка, diff меньше 15%, набор ссылок и чисел не изменился: агент `edit-patcher` на Sonnet точечно вносит ту же правку во все черновики;
  - иначе: полный повтор анализа и адаптации.

### 3.3 Проверка свежести и удаления в T+60

В Bot API нет события «пост в канале удалён», поэтому код проверяет это сам.

- **Основной метод:** `forwardMessage` (для альбома `forwardMessages`) из канала в приватный служебный канал, где бот — админ и где никто не получает уведомлений. Параметр `disable_notification=true`.
  - Ошибка `message to forward not found` или похожая означает, что пост удалён: статус `deleted`, задачи публикации отменяются, автор получает уведомление.
  - Успешный ответ возвращает объект `Message` с **текущими** текстом и entities. Код сверяет `content_hash` с версией, по которой делались черновики, и при расхождении запускает пересчёт (это страховка на случай потерянного `edited_channel_post`). Затем пересланная копия удаляется через `deleteMessage`.
- **Если включена защита контента** (`has_protected_content`), пересылка не сработает. **[проверить]**, работает ли тогда `copyMessage`. Запасной вариант — считать пост живым, если за последние 60 минут не было признаков удаления, и сказать автору, что проверка недоступна.
- Перед публикацией в каждую следующую сеть проверка не повторяется. Но если во время публикации пришёл `edited_channel_post`, срабатывает политика правок после публикации (§8.5).
- Вся процедура **[проверить]** в фазе 0 на тестовом канале: удаление, правка, альбом, защищённый контент.

### 3.4 Анализ (один раз на версию поста)

Сначала работает код:

1. **Фильтр рекламы.** Регулярные выражения на `erid` (в тексте и в query-параметрах URL), «Реклама», «#реклама», «на правах рекламы», «партнёрский материал», ИНН и ОГРН рекламодателя. Любое совпадение даёт `skipped:ad`. Реклама не уходит никуда, автору идёт короткое уведомление.
2. **Фильтр VPN и обхода блокировок.** Словарь плюс домены из класса `circumvention`. Совпадение даёт `held:vpn` и вопрос автору. Само слово «VPN» в нейтральном контексте («корпоративный VPN») — частый ложный позитив. Поэтому совпадение не отменяет пост, а отправляет его на ручное решение. При этом в RU-сетях такой пост автоматически не публикуется никогда.
3. **Извлечение и классификация ссылок** (§4).

Затем запуск `post-analyst`. Он выдаёт:
- тип поста, тему, главный тезис;
- ключевые факты (`must_keep`), которые судья потом сверяет;
- роль и важность каждой ссылки;
- `is_ad_suspect` с доказательствами;
- флаги рисков: VPN, политика, медицина, упоминание Meta, похожее на рекламу;
- пригодность для каждой сети и оценку пригодности для рилса.

Если `is_ad_suspect=true`, пост переходит в `held` и автор получает вопрос.

### 3.5 Адаптация под каждую сеть

Для каждой включённой сети запускается свой writer-агент. Входные данные:
- IR текста;
- анализ;
- манифест ссылок с решениями **для этой сети**;
- описание медиа;
- ограничения сети;
- предыдущая попытка с ошибками валидатора и замечаниями судьи, если она была.

На выходе — `draft` по схеме (§6.6). Писатели запускаются последовательно, чтобы общий префикс промпта (агент плюс author-voice) успевал закешироваться.

### 3.6 Валидация

- **Код-валидаторы** (§5, раздел «валидатор» у каждой сети) работают всегда.
- **Судья** (`judge`) — один запуск на все черновики поста. Он сравнивает факты, числа, имена и смысл с оригиналом, проверяет голос автора и соответствие площадке. По каждой сети ставит вердикт `pass`, `fix` или `block`.
- **Повторы:** на сеть не больше двух перегенераций с замечаниями. Если черновик так и не прошёл, сеть получает `held`, а автор — черновик и кнопки «Опубликовать как есть», «Править», «Пропустить».
- Threads по-прежнему публикуется без одобрения. Одобрение запрашивается только когда валидатор или судья не пропустили черновик.

### 3.7 Публикация

- Порядок: **Threads → FB → MAX → VK → IG**. Threads первым, потому что FB вставляет его permalink.
- Если пост ссылается на собственный TG-пост, который ещё ждёт в буфере, задача ставится в зависимость и ждёт, пока тот опубликуется.
- Протокол идемпотентности описан в §8.1.

### 3.8 Запись соответствий и отчёт

- `publications` хранит `remote_id`, `remote_url`, служебные ID: цепочки Threads, комментарии FB и VK.
- `tg_link_aliases` пополняется всеми формами ссылки на исходный пост: `t.me/<ch>/<id>`, `telegram.me/...`, `t.me/s/...`, `t.me/c/<internal>/<id>`, `tg://resolve?domain=..&post=..`.
- **Отчёт** уходит автору в личку от бота (вопрос: может, нужен в комментарии к посту):

```
Пост 07.10 «Как я выбираю AI-инструменты…» → t.me/…/1234
MAX: опубликован — https://max.ru/… (или «канал приватный, ссылки нет», id 5678)
VK: опубликован — https://vk.ru/wall-…_…
Threads: опубликован (цепочка из 3) — https://www.threads.com/@…/post/…
FB: опубликован без внешних ссылок (бюджет 1/2) — https://facebook.com/…
Замены ссылок: 4 (показать) · Предупреждения: 0
[Повторить VK] [Удалить везде] [Показать тексты]
```

## 4. Движок политики ссылок

### 4.1 Шаги (всё делает код)

1. **Извлечение:** entities `url` и `text_link` (поле `entity.url`), `mention`, `text_mention`, а также `erid` в URL.
2. **Нормализация:**
   - убрать `utm_*`, `fbclid`, `si` и подобные параметры;
   - привести хост к нижнему регистру, `www.` убрать;
   - `telegram.me` и `t.me` считать одним доменом (в июле 2026 `t.me` отключался);
   - раскрыть сокращатели (bit.ly, clck.ru, vk.cc, t.co, lnkd.in, goo.su) через HEAD или GET с сервера: не больше 5 редиректов, таймаут 5 с.
3. **Классификация по таблице `domain_policy`** и разбор ссылок на Telegram:

4. **Принятие решения для каждой ссылки и каждой сети** по таблице 4.3. Результат пишется в `link_decisions`.
5. **Исследование** (только если решение `research`). `link-researcher` получает очищенное содержимое страницы:
   - для чужого публичного TG-поста — сервер забирает `t.me/<ch>/<id>?embed=1`, из Испании он доступен;
   - для ссылки на X, LinkedIn, YouTube — открытые метаданные или oEmbed.

   Researcher ищет **первоисточник** среди ссылок внутри этого контента (сайт компании, статья, репозиторий). Каждый найденный кандидат снова проходит классификацию кодом. Принимается только кандидат, доступный в RU. Если такого нет, ссылка пересказывается.
6. **В манифест для writer** попадают: `ref`, анкор из оригинала, класс, `action` для этой сети, `target_url` (не показывается модели, только «тип цели»), `label_hint`, краткое содержание целевой страницы, если оно есть.
7. **Рендер.** Рендерер подставляет URL по ref. Валидатор проверяет, что в тексте нет `http`, `www.`, `t.me` и вообще URL вне манифеста.

### 4.2 Откуда берутся статусы доменов

Обновление раз в сутки, задача `policy-updater`. Приоритет источников:

1. ручной override автора (`config/domain_overrides.yaml`);
2. списки itdoginfo/allow-domains: `Services/*` (telegram, meta, youtube, twitter, discord), `Categories/geoblock.lst`, `Categories/block.lst`;
3. OONI aggregation, `probe_cc=RU`, окно 30 дней. Доля аномалий = (anomaly+confirmed)/n. При n ≥ 100: 50% и выше — `blocked`, 15–50% — `throttled`; при n < 100 — `unknown`;
4. antifilter.download `domains.lst` как сигнал `blocked_rkn`;
5. Globalping — только для неизвестных доменов и с низким весом.

zapret-info не используется: не обновлялся с 2025 года. Списки itdoginfo и antifilter ведут сообщества, которые занимаются обходом блокировок. Мы используем их **только как данные на чтение** и никогда не упоминаем в контенте. Модель не решает, заблокирован ли домен.

## 5. Спецификации по сетям

У каждой сети одинаковая структура: аудитория, ссылки, форматирование и лимиты, медиа, тон, CTA и хэштеги, публикация через API, валидатор. Эти разделы почти дословно ложатся в `SKILL.md` соответствующей сети.

### 5.1 MAX

- **Аудитория:** Россия, преимущественно мобильная, часть на «белых списках». Telegram, Meta, X, LinkedIn и YouTube не открываются. Это читатели в мессенджере, по ощущению ближе всего к TG-каналу.
- **Канал.** Сейчас приватный, поэтому `Message.url = null` и у постов нет ссылок. Рекомендуется:
  - (а) верифицироваться как самозанятый на business.max.ru и через `@business_channel_bot` перевести канал в публичный с ником `channel_<ник>`. В профиле канала будет видно ФИО самозанятого;
  - (б) если TG-канал зарегистрирован в РКН, использовать путь А+ через `@channel_bot`: ник будет тот же, что в Telegram.

  Формат URL поста в публичном канале не документирован. Его нужно брать из ответа API как есть **[проверить]**.
- **Форматирование:** `format=html`. Рендерер IR→HTML использует только `<b> <i> <u> <s> <a href> <code> <pre> <blockquote>`:
  - `expandable_blockquote` превращается в `<blockquote>`;
  - `<h1>` и `<mark>` не используются;
  - `spoiler` становится обычным текстом.
- **Лимиты:** текст до 4000 символов, рабочий потолок 3800. Если исходник длиннее, writer сжимает текст. Разбиение на два сообщения разрешено только по флагу.
- **Ссылки** («показывать отдельным текстом или правильно вставлять кодом»):
  - скрытые ссылки из TG (`text_link`) становятся `<a href>` с тем же анкором — именно это теряли «технические репосты»;
  - голые URL становятся `<a>` с коротким человекочитаемым анкором (домен или название);
  - **главная ссылка** (CTA, первоисточник) дублируется кнопкой `inline_keyboard` типа `link`: подпись до ~30 символов, не больше 3 кнопок в ряд, не больше 2 кнопок на пост;
  - `disable_link_preview=true`, если у поста есть медиа или в нём больше одной ссылки; иначе превью разрешено для главной ссылки.
- **Медиа.** Схема загрузки: `POST /uploads?type=image|video|file`, затем upload, затем `attachments[{type, payload:{token}}]`. Ограничения:
  - до 12 изображений, видео до 250 МБ;
  - при ошибке `attachment.not.ready` повторы с задержкой 1, 2, 4… с, суммарно до 2 минут;
  - `type=photo` больше не поддерживается, нужно `image`;
  - документы из TG уходят как `file`.
- **Тон:** практически 1:1 с TG, тот же голос. Код и writer убирают специфику Telegram: «в комментариях к посту» (если комментарии в MAX-канале выключены **[проверить]**), «реакции», «бусты», «закреп», «подписывайтесь в TG», «сторис». В MAX-посте не упоминается, что это копия из Telegram.
- **CTA и хэштеги:** хэштеги не ставить, их навигационная роль в MAX не подтверждена. CTA — вопрос читателю, только если комментарии включены.
- **Правовое:** нет VPN и обхода, нет рекламы, сноска про Meta по флагу.
- **API.** `POST https://platform-api2.max.ru/messages?chat_id=…`, токен в заголовке `Authorization`, не больше 2 сообщений в секунду на чат.
  - TLS: бандл «Russian Trusted Root/Sub CA» передаётся **только** HTTP-клиенту MAX (`verify=certs/russian_trusted.pem`), в системное хранилище не добавляется.
  - `chat_id` берётся один раз через `GET /updates` после добавления бота админом (событие `bot_added`).
  - Правка поста — `PUT /messages?message_id=…`, без ограничения по давности.
- **Валидатор:** длина ≤ 4000 после рендера; только разрешённые теги, HTML корректно сбалансирован; нет URL с доменами из классов `meta / blocked_ru / tg_* / circumvention`, кроме разрешённых манифестом; кнопки ≤ 3 в ряд, URL ≤ 2048; нет слов «VPN», «впн», «обход блокиров», «прокси для»; сноска Meta на месте, если Meta упомянута, а флаг включён; все ref разрешены.

### 5.2 VK

- **Аудитория:** Россия и русскоязычные за рубежом. Это лента: после 3–4 строк пост сворачивается в «Показать полностью», поэтому первые 2 строки — хук.
- **Доступ:**
  - **Основной путь:** пользовательский токен Standalone-приложения с правами `wall,photos,video,offline` (Implicit Flow). Права `wall` и `video` выдаются только по запросу на devsupport@corp.vk.com, письмо отправляем в день 1. Токен привязан к IP, поэтому получать его нужно **в браузере на самом сервере** (или на ретрансляторе, если трафик к VK идёт через него). Все вызовы — на `api.vk.ru`, ссылки хранить как `https://vk.ru/wall-<gid>_<pid>`.
  - **Запасной путь (браузер):** если права не дадут. Playwright с persistent-профилем, автор один раз входит через noVNC.
    - Шаги: открыть страницу сообщества → композер → вставить текст (уже адаптированный и провалидированный) → загрузить медиа → дождаться сниппета главной ссылки → «Опубликовать» → прочитать URL поста → сделать скриншот для отчёта.
    - Капчи не решаем: при появлении капчи сеть получает статус `paused`, автору уходит алерт.
    - Селекторы вынесены в конфиг. Если UI поменялся, публикация в VK падает в `held` вместо того чтобы ломать конвейер.
    - Этот путь хрупкий, и с точки зрения правил VK автоматизация UI — серая зона.
  - Токены сторонних клиентов (Kate Mobile и т. п.) не использовать.
- **Форматирование:** у `wall.post` форматирования нет. Структура держится на абзацах, коротких строках и умеренных маркерах-эмодзи (по стилю автора). Длина до 16 384, рабочий потолок 4000.
- **Ссылки:**
  - внешняя ссылка-сниппет во вложении — **ровно одна**. Это главная ссылка: `wall.parseAttachedLink`, затем `link_title` и `link_photo_id`, если превью не собралось;
  - остальные внешние ссылки — голым URL в тексте;
  - анкоры `[https://vk.ru/wall-…|текст]` работают только для объектов VK, поэтому собственные посты из таблицы соответствий оформляются анкорами;
  - второстепенные ссылки можно вынести в первый комментарий (`wall.createComment`), по флагу. Влияние внешних ссылок на охват не доказано, это вопрос для A/B **[низкая уверенность]**.
- **Медиа:**
  - фото: `photos.getWallUploadServer`, затем загрузка, затем `photos.saveWallPhoto`, до 10 во вложениях;
  - видео: `video.save` (право `video`, лимит 5000 вызовов в сутки, ошибка 704 означает «нужна 2FA»);
  - клипы — только браузер, фаза 3.
- **Тон:** чуть больше контекста, чем в TG, сильный хук в первой строке. Проще, без «телеграмного» сленга.
- **CTA и хэштеги:** 1–3 хэштега в конце (если это сообщество — `#тег@club`), CTA — вопрос в комментарии.
- **Правовое:** то же, что для MAX, плюс никогда не ставить `mark_as_ads` (рекламу мы вообще не публикуем).
- **API:** `wall.post(owner_id=-gid, from_group=1, message, attachments, guid=<idem_key>)`. Параметр `guid` защищает от дублей примерно в течение часа. Правка — `wall.edit`.
- **Валидатор:** не больше одной внешней ссылки во вложении; в тексте нет Markdown или HTML; анкоры только на vk.ru и vk.com; те же запретные домены и слова, что в MAX; хэштегов ≤ 3.

### 5.3 Facebook Page

- **Аудитория:** в РФ FB заблокирован, поэтому читатели — русскоязычные за рубежом и международная аудитория, если автор захочет писать на английском (вопрос).
- **Лимит ссылок.** По официальной справке, у страниц под тестом — 2 органических поста **или комментария** со ссылкой в месяц, ссылка в первом комментарии тоже считается. Бесплатно:
  - дополнительные ссылки в комментариях к посту, где ссылка уже есть;
  - ссылки на сервисы Meta (Facebook, Instagram, WhatsApp, Threads);
  - партнёрские ссылки и реклама.

  t.me — внешняя ссылка, она расходует лимит.
- **Политика:**
  1. По умолчанию **0 внешних ссылок.** Текст самодостаточен, сервисы названы словами.
  2. Строка «Все ссылки из поста — в Threads: <permalink>» (флаг `fb_links_via_threads=true`), если у поста были ссылки и Threads опубликован успешно.
  3. Ссылки на собственные FB-посты из таблицы соответствий бесплатны и разрешены.
  4. Бюджет `link_budget(fb, YYYY-MM)` = 2, сброс 1-го числа. Тратится только на ссылки с ролью `own_promo` и важностью 3 по анализу **и** после подтверждения автора одной кнопкой в предпросмотре. Под таким постом все остальные ссылки можно добавлять комментариями (`POST /{post-id}/comments`, разрешение `pages_manage_engagement`): это бесплатно.
  5. Проверка после публикации: `GET /{post-id}?fields=attachments`. Если карточки ссылки нет, считаем, что лимит исчерпан (бюджет обнуляется), и шлём автору алерт. Поведение при превышении официально не описано **[низкая уверенность]**.
  6. Постоянные ссылки (TG-канал, сайт) лежат в Links страницы, в постах — «ссылка в профиле страницы».
  7. Meta One ради ссылок не покупать: Advanced (€54.99) даёт 8 ссылок, это нерационально.
- **Форматирование:** обычный текст, без Markdown и без «юникод-жирного». Хук в первых ~2 строках: длинный пост сворачивается в «See more».
- **Медиа:**
  - одно фото: `/{page}/photos`;
  - несколько: неопубликованные фото, затем `attached_media` в `/{page}/feed`;
  - вертикальное видео ≤90 с: `/{page}/video_reels`, три фазы;
  - остальное видео: `/{page}/videos`.
- **Тон:** спокойнее и разговорнее. Убирается контекст, понятный только в России. Вопрос в конце для обсуждения.
- **CTA и хэштеги:** 0–2 хэштега, CTA — комментарий.
- **API:** `POST /{page_id}/feed` (Page token из долгоживущего user token не истекает), разрешения `pages_manage_posts, pages_read_engagement, pages_show_list`. Правка — `POST /{post_id}` с `message`.
- **Валидатор:** число внешних URL не больше доступного бюджета (по умолчанию 0); ссылки на Meta разрешены; нет t.me, если на него не потрачен бюджет.

### 5.4 Threads

- **Аудитория:** международная и русскоязычная техническая, формат быстрый и разговорный. Telegram здесь открывается, MAX и VK бесполезны.
- **Лимиты:**
  - 500 символов на пост; как считаются эмодзи — **[низкая уверенность]**, валидатор считает каждый эмодзи за 4 символа;
  - не больше 5 уникальных URL на пост, включая `link_attachment`; при превышении ошибка `THREADS_API__LINK_LIMIT_EXCEEDED`;
  - `link_attachment` и `text_attachment` (до 10 000 символов, одна ссылка) — только в TEXT-постах;
  - одна тема `topic_tag` (1–50 символов, без точек и `&`);
  - 250 постов в сутки;
  - медиа только по публичному URL.
- **Стратегия длины:**
  - до 500 символов — один пост;
  - 500–1800 символов или пост с медиа — цепочка из 2–4 постов через `reply_to_id`, медиа в первом. Каждая часть должна читаться отдельно, первая — хук;
  - больше 1800 символов без медиа — хук до 500 плюс `text_attachment` с полной адаптацией.
- **Ссылки:**
  - собственный TG-пост заменяется permalink Threads-копии, если она есть, иначе `t.me` остаётся;
  - ссылки MAX и VK заменяются на TG или пересказ;
  - главная ссылка в TEXT-посте идёт через `link_attachment` (карточка), в постах с медиа — текстом.
- **Тон:** короче и живее, без канцелярита. Можно от первого лица и с прямым вопросом аудитории.
- **CTA и хэштеги:** без хэштегов в тексте, один `topic_tag` от writer.
- **Правка после публикации:** в API нет **[проверить]**. Для фактических ошибок — кнопка «Удалить и перевыложить».
- **API:** создать контейнер (`/me/threads`), подождать около 30 с или проверить статус, затем `threads_publish`, затем получить `permalink`. Long-lived token 60 дней, обновляется через `th_refresh_token`.
- **Валидатор:** каждая часть ≤ 500 по консервативному счёту; не больше 5 уникальных URL на пост; `link_attachment` только в TEXT; в цепочке не больше 5 частей; `topic_tag` валиден.

### 5.5 Instagram (фаза 3)

- **Подключение:** профессиональный аккаунт, привязанный к FB-странице, через **Instagram API with Facebook Login**. Это один пайплайн токенов со страницей, resumable upload без публичного URL и опросы. Требования **[проверить]** на аккаунте автора.
- **Только-текст нельзя.** Варианты:
  - у поста есть фото — используются они (карусель);
  - пост только текстовый — writer выдаёт `slides[]` (3–7 слайдов, ≤ 25 слов на слайд), а код рендерит карусель 1080×1350 (4:5) брендовым шаблоном: Remotion `renderStill` или HTML через Playwright, OFL-шрифты с кириллицей, типограф. ИИ-картинки здесь не нужны.
- **Подпись:** до 2200 символов, хук в первых ~125 символах. **Ссылок нет**: в подписи они некликабельны. Используется «ссылка в профиле» (до 5 ссылок в био бесплатно). В фазе 4 по желанию — «напишите слово в комментарии, пришлю в директ» через Private Replies.
- **Хэштеги:** 3–5. API допускает 30, но с декабря 2025 говорят о лимите 5 **[низкая уверенность]**, поэтому держимся 5.
- **Медиа-URL:** через nginx по случайному ASCII-пути с TTL 2 часа, robots не закрывает, доступ для `facebookexternalhit`. Опрос контейнера раз в минуту, не дольше 5 минут. Лимиты: 100 постов и 400 контейнеров в сутки.
- **ИИ:** `is_ai_generated=true`, если в медиа есть заметный фотореалистичный ИИ-контент.
- **Правка подписи после публикации:** поддерживается ли через API — **[проверить]**, по умолчанию правка не переносится.

## 6. LLM-слой: агенты, скиллы, MCP, запуск

### 6.1 Что чем реализуется

| Сущность | Что это | Почему |
|---|---|---|
| **Демон (код)** | Оркестрация, решения о ссылках, бюджет, публикация | Детерминизм, идемпотентность, никаких лимитов LLM на логистику |
| **Агент** (`.claude/agents/*.md`, запуск `--agent`) | Роль одного LLM-шага: промпт, модель, инструменты, предзагруженные скиллы | Один запуск — одна роль, свои права и своя модель |
| **Скилл** (`.claude/skills/*/SKILL.md`) | Переиспользуемое знание: голос автора, правила сети, политика ссылок, чек-лист судьи | Открытый формат, переносится в Codex; автор может пользоваться теми же скиллами в интерактивном Claude Code |
| **Субагенты внутри запуска** | **Не используются** | Вложенные запуски хуже контролируются, повторяются и считаются. Распараллеливает демон |
| **MCP-сервер `smm`** | Инструменты только для чтения: самопроверка, примеры, статусы, безопасное чтение веба для researcher | Один stdio-сервер работает с Claude, Codex и OpenAI Agents SDK |
| **Публикация как инструмент** | **Запрещена** | Rule of Two: модель не меняет внешний мир |

### 6.5 Как демон вызывает LLM

Задание передаётся через stdin. Шаблон для writer:

```bash
cd /srv/neuro-smm/agent && \
env -i HOME=/srv/neuro-smm PATH=/usr/local/bin:/usr/bin \
  CLAUDE_CONFIG_DIR=/srv/neuro-smm/claude-config \
  CLAUDE_CODE_OAUTH_TOKEN="$(cat /run/secrets/claude_oauth)" \
  CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 \
  ENABLE_TOOL_SEARCH=false \
claude -p \
  --agent writer-vk \
  --setting-sources project \
  --mcp-config ./mcp.json --strict-mcp-config \
  --tools "" \
  --allowedTools "mcp__smm__validate_draft,mcp__smm__get_examples" \
  --permission-mode dontAsk --permission-prompts none \
  --model opus --effort medium --fallback-model sonnet \
  --max-turns 6 --max-budget-usd 1.5 \
  --output-format json --json-schema "$(cat schemas/draft.json)" \
  --no-session-persistence \
  < /srv/neuro-smm/data/jobs/<job_id>.json
```

Команды для остальных агентов:

```bash
# Анализ (без инструментов)
claude -p --agent post-analyst ... --tools "" --disallowedTools "mcp__*" \
  --model opus --effort medium --max-turns 2 --json-schema "$(cat schemas/analysis.json)" < job.json

# Судья (все черновики поста за один запуск)
claude -p --agent judge ... --tools "" --disallowedTools "mcp__*" \
  --model sonnet --max-turns 2 --json-schema "$(cat schemas/judge.json)" < judge_job.json

# Researcher (единственный, кто видит недоверенный веб; записи нет)
claude -p --agent link-researcher ... --tools "" \
  --allowedTools "mcp__smm__fetch_url_summary,mcp__smm__tg_post_preview,mcp__smm__domain_status" \
  --model sonnet --max-turns 6 --json-schema "$(cat schemas/research.json)" < research_job.json
```

Правила раннера:

- **Успех** — только `is_error=false`, `subtype=="success"` и непустой `structured_output`. Всё остальное — ошибка с классификацией:
  - `rate_limit` или `session limit`: задача переносится до сброса окна либо уходит на запасной раннер;
  - `overloaded`: повтор через 30–120 с;
  - `error_max_turns` или `error_max_structured_output_retries`: повтор с упрощённым заданием, затем `held`;
  - `authentication_failed`: алерт автору, LLM-очередь ставится на паузу.
- **В `llm_runs` пишутся** `session_id, num_turns, usage, modelUsage, total_cost_usd, permission_denials, errors, duration_ms`.
- **Смоук-тест при старте и после обновления CLI.** Запуск `claude -p --output-format stream-json` на тестовом задании. В событии `system/init` проверяется, что загрузились скиллы агента и MCP-сервер `smm` без `mcp_server_errors`. Загрузка `skills:` при запуске через `--agent` — **[проверить]**. Если скиллы не подгрузились, раннер переходит в «скомпилированный» режим: `--system-prompt-file compiled/writer-vk.md`, где файл собран как агент плюс тексты скиллов.
- **Флаги** `--permission-prompts none`, `omitClaudeMd`, `ENABLE_TOOL_SEARCH`, поведение `--tools ""` взяты из документации на 10.2026 через исследование. Их нужно сверить с `claude --help` закреплённой версии **[проверить]**.
- **Подписка:** без `--bare`. Версия закреплена (`claude install <x.y.z>`, автообновление выключено). `ANTHROPIC_API_KEY` в окружении отсутствует: `env -i` это гарантирует. `setup-token` действует год, напоминание за 30 дней.

### 6.6 Схемы (строгое подмножество, совместимое с OpenAI strict)

Все поля перечислены в `required`, `additionalProperties:false`, необязательные поля заданы через `["type","null"]`.

`draft.json` (сокращённо):

```json
{"type":"object","additionalProperties":false,
 "required":["network","skip","skip_reason","parts","buttons","main_link_ref","hashtags","topic_tag",
             "media_plan","footnotes","notes_for_author","self_check"],
 "properties":{
  "network":{"type":"string","enum":["max","vk","fb","threads","ig","tg_video"]},
  "skip":{"type":"boolean"}, "skip_reason":{"type":["string","null"]},
  "parts":{"type":"array","minItems":1,"maxItems":5,"items":{"type":"object","additionalProperties":false,
     "required":["text","media_refs"],"properties":{"text":{"type":"string"},
     "media_refs":{"type":"array","items":{"type":"string"}}}}},
  "buttons":{"type":"array","maxItems":2,"items":{"type":"object","additionalProperties":false,
     "required":["label","ref"],"properties":{"label":{"type":"string"},"ref":{"type":"string"}}}},
  "main_link_ref":{"type":["string","null"]},
  "hashtags":{"type":"array","items":{"type":"string"}},
  "topic_tag":{"type":["string","null"]},
  "media_plan":{"type":"object","additionalProperties":false,
     "required":["use_source_media","order","slides","cover_text"],
     "properties":{"use_source_media":{"type":"boolean"},"order":{"type":"array","items":{"type":"string"}},
       "slides":{"type":"array","items":{"type":"string"}},"cover_text":{"type":["string","null"]}}},
  "footnotes":{"type":"array","items":{"type":"string","enum":["meta_extremist"]}},
  "notes_for_author":{"type":["string","null"]},
  "self_check":{"type":"object","additionalProperties":false,
     "required":["facts_preserved","links_per_manifest","validator_ok"],
     "properties":{"facts_preserved":{"type":"boolean"},"links_per_manifest":{"type":"boolean"},
       "validator_ok":{"type":"boolean"}}}}}
```

`analysis.json` — ключевые поля:
- `is_ad_suspect`, `ad_evidence[]`;
- `post_type` (news, tool_review, howto, opinion, announcement, digest, personal);
- `topic`, `thesis`;
- `key_facts[{fact, must_keep}]`, `entities[{name, kind}]`;
- `links[{ref, role: source|tool|own_promo|reference|example|cta, importance: 1-3, note}]`;
- `networks_fit{max,vk,fb,threads,ig:{publish, reason}}`;
- `risk_flags[]`, `reel_score` (0–1), `tone_notes`.

`judge.json`:
- `verdicts[{network, verdict: pass|fix|block, issues[{severity, text}], fix_instructions}]`.

### 6.7 Замена вендора

- **Интерфейс:**

  ```python
  class LLMRunner(Protocol):
      def run(self, agent: str, payload: dict, schema: dict, *, model_hint: str | None = None) -> RunResult
  ```

- **Реализации:**
  - `ClaudeCliRunner` — по умолчанию;
  - `CodexExecRunner`:
    ```
    codex exec --skip-git-repo-check --sandbox read-only -m <model> --output-schema schemas/draft.json -o out.json
    ```
    Рабочий каталог `agent/compiled/codex/<agent>/` с `AGENTS.md` (агент плюс скиллы). MCP `smm` подключается через `config.toml`. Скиллы Codex ищет в `.agents/skills`;
  - `OpenAIResponsesRunner` — системный промпт из `compiled/<agent>.md`, `text.format={type:json_schema, strict:true}`. Вместо MCP наш цикл до 3 раз вызывает функцию `validate_draft` как function tool.
- **Всё, что нужно для понимания, уже лежит во входном JSON**: манифест ссылок с решениями, соответствия, 2–3 примера. Инструменты только помогают самопроверке, поэтому любой раннер работает и без них. Финальная валидация всё равно делается в демоне.
- **`config/models.yaml`** задаёт для каждого агента `primary` и `fallback`:

  ```yaml
  writer-vk:   {primary: {runner: claude, model: opus, effort: medium}, fallback: {runner: openai, model: gpt-6.1-sol}}
  judge:       {primary: {runner: claude, model: sonnet}, cross_check: {runner: openai, model: gpt-6.1-sol}}
  ```

  ID моделей OpenAI нужно сверить через `/v1/models` **[проверить]**: в источниках встречаются и «GPT-6.1 Sol», и «gpt-5.6-sol».
- **Цепочка при исчерпании лимита подписки:**
  1. отложить задачу, если до дедлайна больше 20 минут;
  2. иначе — запасной раннер (OpenAI API-ключ с лимитом расходов) или, по флагу, Anthropic API-ключ, переданный **только в окружение этого одного процесса**;
  3. иначе `held` и уведомление.
- **Выбор модели.** Старт: Opus 5.5 для анализа и writer, Sonnet 5.5 для судьи, researcher и патчера. В фазе 2 — слепой A/B на 20–30 прошлых постах (Opus 5.5, Sonnet 5.5, GPT-6.1 Sol, GPT-6 Astra), автор оценивает по чек-листу «голос / смысл / ссылки». Надёжного бенчмарка русского копирайтинга нет **[низкая уверенность]**.
- **Расход:** 1 анализ, 4–5 writer, 1 судья, иногда researcher или перегенерация — 6–9 запусков на пост. В пересчёте на цены API это около $1–2 за пост **[низкая уверенность, оценка]**. Pro может не хватить, если автор сам много работает в Claude. Рекомендуется Max 5x, реальные цифры снимаем за первую неделю.

### 6.8 Как агент «понимает» и учится

1. **Эталонные пары.** Перед запуском автор утверждает 10–20 пар «TG-пост → идеальная версия» для каждой сети. Черновики пар сгенерирует система, автор правит.
2. **Исправления.** Всё, что автор поправил в предпросмотре или после публикации (ответом с текстом или командой `/fix`), попадает в `corrections`.
3. **Сводка уроков.** Раз в неделю `lessons-curator` сводит исправления в предложенные правки `author-voice/taboo.md`, `glossary.md`, `net-*/SKILL.md` и `examples/` в виде diff. Diff уходит автору, и только после «ОК» демон коммитит изменения: каталог `agent/` лежит в git. Скиллы сами себя не переписывают.
4. **Глоссарий.** Названия продуктов, как писать «ИИ / AI», транслитерации, запрещённые штампы.

## 8. Надёжность и эксплуатация

### 8.1 Идемпотентность публикации

1. `idem_key = sha256(post_id|channel|adaptation_id)`.
2. В одной транзакции: `state=publishing`, `attempt_started_at=now`, `attempts+=1`. Затем вызов API. Затем в одной транзакции `state=published`, `remote_id`, `remote_url`, `published_hash`.
3. **Сверка после рестарта.** Если запись в `publishing` старше 2 минут, перед повтором проверяем, не опубликован ли пост уже. Ищем среди последних 20 постов сети совпадение нормализованного хэша первых 200 символов:
   - MAX — `GET /messages?chat_id`;
   - VK — `wall.get`, плюс `guid` даёт защиту от дублей самого API;
   - FB — `/{page}/posts?fields=message`;
   - Threads — `/me/threads?fields=text`;
   - IG — `/me/media?fields=caption`.
4. **Цепочка Threads** хранит id каждой опубликованной части в `remote_extra_json`. Повтор продолжает с первой неопубликованной части.

### 8.2 Повторы и частичные сбои

| Ошибка | Действие |
|---|---|
| Сеть, таймаут, 5xx | Повтор с экспоненциальной задержкой и джиттером: 30 с, 2, 8, 30 мин, 2 ч (до 5 попыток) |
| 429 / rate limit | Ждать `retry_after`, не тратя попытку |
| MAX `attachment.not.ready` | Отдельный цикл 1, 2, 4… с, суммарно до 120 с |
| IG/Threads контейнер `IN_PROGRESS` | Опрос раз в 30–60 с, до 5 минут; `ERROR` или `EXPIRED` → пересоздать один раз |
| Авторизация, токен | Сеть в `paused`, алерт с инструкцией |
| Валидация, политика (VK 222, Threads link limit) | Без повтора: перегенерация writer с текстом ошибки, затем `held` |
| Бюджет FB исчерпан | Переписать без ссылок (writer с флагом), алерт |

- Каждая сеть публикуется независимо. Пост получает `partial`, если хотя бы одна сеть упала. В отчёте у неё кнопка «Повторить».
- **Circuit breaker:** 3 подряд неудачи по одной сети ставят паузу на 1 час и шлют уведомление.

### 8.3 Зависимости

- FB ждёт Threads не дольше 10 минут. Если Threads упал, FB уходит без строки про Threads.
- Пост со ссылкой на свой пост, который ещё в буфере, ждёт его публикации в той же сети не дольше 2 часов. Потом ссылка пересказывается.

### 8.4 Удаление

- **До публикации:** проверка в T+60 (§3.3).
- **После публикации:** раз в сутки forward-проверка постов за последние 7 дней. Если пост удалён, автор получает кнопку «Удалить везде». Сами ничего не удаляем.

### 8.5 Правка после публикации

| Сеть | Механизм | Политика по умолчанию |
|---|---|---|
| MAX | `PUT /messages` | Авто |
| VK | `wall.edit` (режим API); в браузерном режиме вручную | Авто (API) / кнопка |
| FB | `POST /{post_id}` message | Авто, если не меняются ссылки |
| Threads | API-правки нет **[проверить]** | Кнопка «Удалить и перевыложить» |
| IG | Правка подписи через API **[проверить]** | Только уведомление |

- **Порядок:** правка в TG, затем `edit-patcher` получает старый исходник, новый исходник и опубликованную версию и выдаёт минимальный патч. Дальше валидаторы.
- **Авто-применение:** если правка в течение 48 часов после публикации, diff меньше 15% и не изменился набор ссылок. Иначе в предпросмотр автору.
- Правки позже 48 часов игнорируются, автор получает уведомление.

### 8.6 Здоровье

- **Пульс:** каждую минуту ping в healthchecks (dead-man switch). Внутренний `/health`: лаг очереди, последний `getUpdates`, свободный диск.
- **Ежедневный самотест:**
  - TG `getMe` и права бота в канале;
  - MAX `GET /me`;
  - VK `users.get`;
  - FB `debug_token` и `/{page_id}`;
  - Threads `/me`;
  - IG `/me`;
  - свежесть `domain_policy` не старше 48 часов;
  - доступность nginx-медиа снаружи.
- **Еженедельно:** смоук-тест `claude -p` со схемой. Ежедневно его не запускаем, чтобы не тратить лимиты.
- **Сторожевое правило:** если за 48 часов не пришло ни одного `channel_post`, автор получает вопрос «всё ли в порядке с ботом».

### 8.7 Токены

| Токен | Срок | Обслуживание |
|---|---|---|
| Telegram bot | бессрочно | — |
| MAX bot | бессрочно | при отзыве — алерт |
| VK user (offline) | бессрочно, привязан к IP | при смене IP получать заново на сервере |
| FB Page | бессрочно (из long-lived user) | `debug_token` ежедневно |
| Threads long-lived | 60 дней | `th_refresh_token`, когда токену больше 7 дней |
| IG long-lived (Instagram Login) | 60 дней | `ig_refresh_token`; при Facebook Login — через Page token |
| Claude setup-token | ~1 год | напоминание за 30 дней |
| OpenAI / Gemini / ElevenLabs API | бессрочно | лимиты расходов в консолях |

### 8.8 Секреты и безопасность

- Секреты лежат в `sops+age`, при старте расшифровываются в tmpfs, права 600, отдельный unix-пользователь `smm`.
- `ANTHROPIC_API_KEY` никогда не попадает в общее окружение.
- Бандл Минцифры используется только клиентом MAX.
- Каталог `agent/` и `.claude/settings.json` не доступны на запись процессу claude. Хуков в проекте нет. Если без `--bare` хуки и `.mcp.json` проекта выполняются без подтверждения, это и есть причина держать каталог закрытым.
- Researcher без записи, писатели без сети, публикует только код.
- noVNC доступен только через SSH-туннель.
- MTProto-сессия (если она появится в фазе 4) хранится зашифрованной, на аккаунте включена 2FA.

### 8.9 Логи, стоимость, бэкапы

- **Логи:** структурированные JSON с ротацией; `audit_log` для всех публикаций и решений автора.
- **Еженедельный отчёт в TG:** посты, публикации по сетям, сбои, LLM-запуски, токены, оценка стоимости, расходы на медиа (API), замены ссылок, использованный бюджет FB.
- **Бэкапы:** каждую ночь `sqlite3 .backup` с шифрованием age на внешнее хранилище, плюс git-история каталога `agent/`.

## 9. Блок «Рилсы» (фаза 3)

### 9.1 Что такое «рилсы в Telegram»: варианты

Отдельного формата Reels в Telegram на 10.2026 нет.

| Вариант | Как | Плюсы | Минусы | Рекомендация |
|---|---|---|---|---|
| **A. Вертикальный видео-пост в канале** | Bot API `sendVideo` (1080×1920, `supports_streaming`, `cover`, подпись ≤1024) | Официально, без рисков; тот же мастер для IG | В ленте это обычный пост, возможен «дубль» | **Да, база** |
| **B. Stories канала через MTProto** | Отдельный тех-аккаунт-админ с правом `post_stories`, Telethon/Kurigram `stories.sendStory`, `pinned` и альбом «Reels», `inputMediaAreaChannelPost` на исходный пост | Ближе всего к «рилсам»; альбом на странице канала | Нужны бусты уровня ≥1; возможно, Premium у админа **[проверить]**; userbot под наблюдением, пометка «неофициальный клиент» | Фаза 4, по желанию |
| **C. Полуавтомат Stories** | Бот присылает автору ролик и deep link `tg://post/video` (или Mini App `shareToStory`), автор публикует от имени канала в 2–3 нажатия | Никаких рисков | Ручной шаг | **Да, вместе с A** |
| D. «Кружок» (`sendVideoNote`) | До 1 минуты, квадрат | — | Не подходит для слайдов с текстом | Нет |
| E. Rich Message с видеоблоком | Bot API 10.1+ | Видео плюс длинный текст в одном сообщении | Новое, отображение в каналах не проверено | Наблюдать |

Где размещать вариант A, чтобы не было дубля, решает автор:
- (а) отдельный пост «видео-версия» через N часов;
- (б) ответ в обсуждении поста;
- (в) только Story (вариант C).

### 9.2 Конвейер

1. **Отбор.** По команде (`/reel` ответом на пост или кнопкой в отчёте), либо `analysis.reel_score ≥ 0.7`, тогда автору уходит предложение. Реклама отсекается тем же фильтром.
2. **Раскадровка** (`reel-storyboard`, Opus, JSON):
   - хук до 2 с;
   - 4–7 сцен, у каждой `display_text` ≤ 10–12 слов, `tts_text` (фонетика: «Claude» → «Клод», «GPT» → «джи-пи-ти», числа словами), `visual{type: kinetic|ai_image|screenshot|ai_clip, prompt|url}`, `duration_s`;
   - `cover_text`, `music_mood`;
   - CTA и подпись для каждой площадки (подписи потом пишут writer-агенты в режиме reel);
   - целевая длительность 20–45 с.
3. **Валидация раскадровки кодом:** длины, суммарная длительность, типограф (неразрывные пробелы, «ёлочки», тире), запретные слова, нет реальных людей и логотипов в `ai_image`-промптах.
4. **Голос:**
   - (а) ElevenLabs, клон голоса автора (Starter или Creator), eleven_v3 или v4, `/with-timestamps` даёт пословные тайминги сразу;
   - (б) бюджетно: Gemini 3.8 Flash TTS с voice replication плюс forced alignment (`whisper-1` word timestamps или локальный whisper.cpp).

   Выбор — слепой A/B на 5 постах. Обратная транскрипция проверяет произношение.
5. **Визуал:**
   - kinetic-типографика (Remotion, без генерации);
   - ИИ-фоны и иллюстрации **без текста**: основной провайдер `gpt-image-2.5-flare` (1024×1536 или 1088×1920, medium/high), запасной Nano Banana 2.1 (9:16, 2K), фиксированный style-prefix и референсы из `brand.yaml`;
   - скриншоты упомянутых сервисов через Playwright (для канала про AI-инструменты это честнее сгенерированных интерфейсов);
   - опционально 1 ИИ-клип на хук.

   Русский текст всегда рендерит код.
6. **Музыка:** Lyria 3 Clip (30 с, $0.04) или ElevenLabs Music, либо своя библиотека с лицензией на все площадки. Ducking под голос. Meta Sound Collection не использовать: ролик идёт в VK, MAX и TG.
7. **Рендер:** Remotion 1080×1920, 30 fps CFR, H.264 High yuv420p, GOP 2 с, AAC-LC 48 кГц 128–192 кбит/с, loudnorm около −14 LUFS, `+faststart`. Требования: ≤ 60 с и ≤ 45 МБ, тогда ролик проходит в FB Reels (≤ 90 с) и через облачный Bot API без локального сервера. Дополнительно:
   - обложка JPEG 1080×1920, ключевой текст по центру, чтобы пережить обрезку до 1:1 в ленте IG;
   - для варианта B — Story-вариант 720×1280 H.265, ключевой кадр каждую секунду, ≤ 30 МБ.
8. **QA:**
   - технический: ffprobe (длительность, размер, кодеки, громкость);
   - `frame-qa` (Sonnet vision) по 8–12 кадрам: мусорный текст на ИИ-картинках, безопасные зоны (текст не под интерфейсом площадок), читаемость;
   - сверка ASR и `tts_text`.

   При сбое — перегенерация конкретной сцены, не больше 2 раз.
9. **Превью автору** в TG: видео плюс кнопки «Опубликовать», «Перегенерировать сцену N», «Другой голос», «Отменить». Подтверждение обязательно минимум первые 4 недели.
10. **Публикация:**
    - TG: `sendVideo` в канал по выбранному варианту размещения, `message_id` в `bot_sent_messages`; вариант C — ролик и deep link автору;
    - IG Reels: контейнер `REELS`, `share_to_feed=true`, `cover_url`, `is_ai_generated` при ИИ-визуале; через Facebook Login — resumable upload;
    - FB Page Reels: `/{page}/video_reels`, три фазы, 3–90 с, 30 в сутки;
    - MAX: видео-сообщение (`/uploads?type=video`, ≤ 250 МБ) с подписью от writer-max;
    - Threads: VIDEO-контейнер по публичному URL;
    - VK Клипы: браузерная автоматизация. `shortVideo.create` не документирован **[низкая уверенность]**. Запасной путь — `video.save` в стену как обычное видео.
11. **Регуляторика ЕС** (ст. 50 AI Act, с 02.08.2026): при клоне голоса или фотореалистичном ИИ — пометка в подписи «озвучено/сгенерировано с помощью ИИ» и `is_ai_generated` в IG. Это не юридическая консультация.

- LLM-шаги идут из подписки Claude.

Подписка ChatGPT **не даёт** API-доступа к генерации картинок, нужен отдельный ключ OpenAI API с Organization Verification (по ВНЖ Португалии). Gemini API — платный тир, у image- и video-моделей нет бесплатного тира.

Видеомодели генерируют русскую речь ненадёжно: Veo и Omni официально полностью поддерживают только английский. Поэтому ИИ-видео используется только как немой B-roll, а голос и субтитры добавляются отдельно.

## 11. Риски и пункты низкой уверенности

**Риски:**

1. **Политика подписки Anthropic.** Перевод `claude -p` и Agent SDK на отдельные кредиты приостановлен 15.06.2026 и может вернуться. `--bare` обещают сделать режимом по умолчанию, а он ломает OAuth. Защита: закреплённая версия, смоук-тест, запасной раннер.
2. **Лимит ссылок FB** — расширяющийся тест, правила уже менялись: комментарии вошли в лимит в 09.2026. Поведение при превышении через API не документировано **[низкая уверенность]**. Исключение для ссылок на Threads Meta может отменить. Всё вынесено в флаги конфига.
3. **VK:** права `wall` и `video` могут не дать. Браузерный путь хрупкий и находится в серой зоне правил. API клипов не документирован **[низкая уверенность]**.
4. **IP дата-центра в Испании** может попасть под антиVPN-фильтры VK и MAX (определение по ASN). С домашнего IP в Португалии проверено, с испанского сервера — нет.
5. **MAX:** приватный канал не даёт ссылок; модерация «по мнению Компании» (п. 3.11.3); как выглядит URL поста публичного канала — **[проверить]**; работает ли верификация через Госуслуги из-за рубежа — **[низкая уверенность]**.
6. **Детекция удаления через `forwardMessage`** — инженерный приём, не документированная функция. Не работает при защите контента **[проверить]**.
7. **Списки блокировок** запаздывают, OONI плохо видит замедления. Белые списки мобильного интернета делают любую зарубежную ссылку ненадёжной для части аудитории.
8. **Правовые риски в РФ:** любое упоминание VPN или обхода блокировок (ч. 18 ст. 14.3 КоАП); реклама на ресурсах с ограниченным доступом. Защита — код-фильтры до и после LLM.
9. **Лимиты подписки общие** с интерактивной работой автора: публикации могут откладываться.
10. **Рилсы:** волатильность моделей и цен; качество кириллицы в ИИ-картинках подтверждено только маркетингом **[низкая уверенность]** (поэтому текст всегда рендерит код); лицензии на музыку; ресурсы сервера для рендера.
11. **Userbot для Stories:** аккаунт под наблюдением, пометка «неофициальный клиент», риск бана.

**Утверждения, которые нужно проверить перед реализацией:**
- загрузка `skills:` у агента, запущенного через `--agent`;
- флаги `--permission-prompts none`, `omitClaudeMd`, `--tools ""` в закреплённой версии;
- формат `mcp.json`;
- подсчёт символов и эмодзи в Threads;
- нет ли API-правки постов Threads и подписей IG;
- лимит хэштегов IG (5 или 30);
- получает ли бот свои `channel_post`;
- как приходят в `channel_post` посты из Rich-редактора;
- нужен ли Premium админу для Stories канала;
- ID моделей OpenAI;
- поштучные цены gpt-image-2.5 для портретного формата;
- оценка расхода $1–2 за пост.

## 13. Ревью: поправки к дизайну (приоритетнее разделов 0–12)

### 13.1 Вердикт ревьюера

Архитектура в целом верная: детерминированный демон, LLM только для работы с текстом, ссылки через плейсхолдеры, публикует только код. Но для объёма около 1 поста в день она заметно переусложнена: 11+ агентов, MCP-сервер, три раннера, OONI/itdoginfo-конвейер, lessons-curator. При этом у неё есть три дыры, из-за которых требование «не терять факты и понимать как автор» на практике не выполнится. (1) Ingest не разбирает посты из нового визуального редактора TG: в Bot API 10.1 (11.06.2026) у Message появилось поле rich_message. (2) Сохранность фактов держится на LLM-судье. Детерминированной сверки чисел, имён и дат нет. (3) Цепочка «чужая страница → researcher → writer → автопубликация (Threads, MAX)» открыта для prompt injection и подмены первоисточника. Ещё два места построены на непроверенных механизмах. Запуск через `--agent`: `omitClaudeMd` в этом режиме официально игнорируется, а предзагрузка `skills:` для основной сессии нигде не описана. И Message.url в MAX: документация прямо говорит только, что ссылки нет для диалогов и групп, а не для приватных каналов. Что предлагаю. MVP (MAX + Threads) собрать из 2–3 LLM-вызовов на пост: «редактор» пишет анализ и все сети сразу, «судья» — на другой модели. Промпт собирать из файлов скиллов через `--system-prompt-file`, MCP не использовать. Валидатор держать в демоне. Добавить детерминированную сверку фактов, парсер rich_message и обязательное одобрение автора для всего, что пришло из research. Всё остальное отложить в фазу 2+.

### 13.2 Перепроверенные утверждения

- **«Рилсов» в Telegram как отдельного формата нет; бот не может опубликовать Story в канал**  
  ПОДТВЕРЖДЕНО. Метод postStory (Bot API 9.0, 11.04.2025) публикует только от имени бизнес-аккаунта: обязательный business_connection_id и право can_manage_stories. Публикации stories в канал (chat_id канала) в Bot API нет. В changelog до 10.3 (24.08.2026) про это ничего нет. Вертикальной ленты видео или «Reels» в Telegram на 10.2026 я не нашёл. Остаются варианты: вертикальный sendVideo в канал (параметр cover с Bot API 8.3), Story вручную или через MTProto-аккаунт. По блогу Telegram (сентябрь 2023) для Stories канала нужны уровень бустов ≥1 и Premium у админа, который публикует. Отменено ли требование Premium к 2026 году, не нашёл [низкая уверенность].
  Источники: https://core.telegram.org/bots/api-changelog, https://docs.aiogram.dev/en/latest/api/methods/post_story.html, https://telegram.org/blog/channel-stories
- **В Bot API нет события удаления поста канала; удаление проверяется через forwardMessage**  
  ПОДТВЕРЖДЕНО в части «события нет». Обновления об удалении есть только для бизнес-аккаунтов (BusinessMessagesDeleted, 7.2). Методов getMessage или getChatMessage нет. Трюк с forwardMessage и ошибкой «message to forward not found» — известный workaround сообщества, официально не документирован. С has_protected_content не сработают ни forward, ни, скорее всего, copyMessage. Дешёвая альтернатива для публичного канала: GET t.me/<ch>/<id>?embed=1 с сервера в Испании. Это не проверено как надёжный сигнал [проверить]. ВАЖНО: в документации к edited_channel_post сказано, что событие может прийти из-за изменения полей, которые бот не использует. Без сравнения content_hash возможны лишние перегенерации.
  Источники: https://core.telegram.org/bots/api, https://bugs.telegram.org/c/735
- **У постов приватного MAX-канала Message.url = null**  
  НЕ ПОДТВЕРЖДЕНО ДОКУМЕНТАЦИЕЙ. Поле url в dev.max.ru описано так: «Публичная ссылка на пост в канале. Отсутствует для диалогов и групповых чатов». О приватных каналах прямо ничего не сказано. Утверждение в дизайне — вывод, а не факт; проверить на тестовом приватном канале в фазе 0. Подтверждено другое: самозанятые с 2026 года могут создавать публичные каналы через business.max.ru с верификацией через Госуслуги. Нативных комментариев в каналах MAX на 02.2026 не было, только сторонние боты-обсуждения. Значит, CTA «напишите в комментариях» в MAX не работает.
  Источники: https://dev.max.ru/docs-api/objects/Message, https://new-retail.ru/novosti/retail/samozanyatye_poluchili_dostup_k_biznes_funktsiyam_maksa/, https://vc.ru/id5714355/2750466-kak-dobavit-kommentarii-v-messendzhere-maks
- **Лимит ссылок FB: 2 в месяц, ссылки в комментариях (включая первый) тоже считаются, ссылки на сервисы Meta (включая Threads) бесплатны**  
  ПОДТВЕРЖДЕНО со средней уверенностью. Официальная страница справки называется «О ссылках в органических публикациях и комментариях Страницы». Тело справки не загрузилось, но заголовок подтверждает, что считаются и комментарии. Пересказ правил (Blotato, 09.2026): ссылки в комментариях Страницы считаются; дополнительные ссылки в комментариях к посту, где ссылка уже есть, бесплатны; исключены ссылки на Instagram, WhatsApp и Threads, партнёрские ссылки и реклама; сброс 1-го числа. Расширение теста — SocialMediaToday, 17.09.2026. Publisher Pages исключены. Советы «ставьте ссылку в первый комментарий» (2025) устарели. Что происходит при превышении через API и выдаётся ли остаток в API, не документировано.
  Источники: https://www.facebook.com/help/1929252614431792, https://www.blotato.com/blog/meta-one-link-limits, https://www.socialmediatoday.com/news/facebook-pages-get-charged-for-link-posts/, https://techcrunch.com/2025/12/17/facebook-is-testing-a-link-posting-limit-for-professional-accounts-and-pages
- **Instagram Reels через API: музыку можно только «зашить» в файл, Meta Sound Collection не использовать**  
  ЧАСТИЧНО УСТАРЕЛО. Есть официальный Instagram Audio API: поиск и прикрепление музыки и original audio к Reels при создании. Ограничения: только Instagram API with Facebook Login, аккаунт Business или Creator, привязанный к Page; каталог ограничен треками, разрешёнными для третьих лиц; превью нет. Решение дизайна держать единый мастер со своей музыкой для всех площадок остаётся разумным. Но для IG можно публиковать вариант без музыки и подключать трек из Audio API (так охват может быть лучше) [низкая уверенность насчёт охвата].
  Источники: https://developers.facebook.com/docs/instagram-platform/content-publishing/audio-api/, https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media
- **У VK Клипов нет официального API, нужен только браузер**  
  СКОРЕЕ НЕВЕРНО. Метод shortVideo.create существует, и в 2025 году им пользовались для загрузки клипов. Жалоба на Хабр Q&A касается того, что после обновления 2025 года у таких клипов выключены комментарии и через shortVideo.edit их не включить.   Источники: https://qna.habr.com/q/1400126
- **claude -p с --agent подгружает skills: из frontmatter и уважает omitClaudeMd; --json-schema даёт строгий JSON**  
  ЧАСТИЧНО ОПРОВЕРГНУТО. Документация sub-agents: при запуске через `--agent` как основной сессии промпт агента заменяет системный промпт. CLAUDE.md и project memory всё равно загружаются, а omitClaudeMd «Ignored when the agent runs as the main session agent via --agent». Поле skills описано как предзагрузка в контекст субагента; работает ли оно для основной сессии, не написано [проверить]. Флаги --json-schema (только print), --tools "" (на MCP не влияет, MCP режется через --disallowedTools "mcp__*"), --permission-prompts none (v2.1.259+), --permission-mode dontAsk, --max-budget-usd (по клиентской оценке), --fallback-model (список), --no-session-persistence, --system-prompt-file и --strict-mcp-config подтверждены в CLI reference. Схемы валидируются как JSON Schema draft-07, более новые версии отклоняются. Успех — только subtype=success с непустым structured_output. Fallback модели может «отозвать» уже готовый ответ и закончиться error_max_structured_output_retries. --bare отключает автообнаружение hooks, skills, субагентов, MCP и CLAUDE.md; несовместимость с OAuth в CLI reference не упомянута [проверить].
  Источники: https://code.claude.com/docs/en/sub-agents, https://code.claude.com/docs/en/cli-reference, https://code.claude.com/docs/en/agent-sdk/structured-outputs

Модель gpt-image-2.5 (Flare/Sunburst) анонсирована 08.09.2026, но по агрегатору находится в early access, цены GA не опубликованы. ### 13.3 Проблемы дизайна и исправления

- **🔴 критично.** Ingest не поддерживает Message.rich_message (Bot API 10.1+). Посты из визуального редактора TG либо уйдут в held, либо потеряют ссылки и форматирование: в блоках RichText ссылки лежат иначе, чем в entities. Если автор пишет длинные посты в редакторе, система не работает именно на «умных» постах.  
  **Исправление:** В фазе 0 опубликовать в тестовом канале пост из редактора и посмотреть сырой update. Написать парсер RichBlock*/RichText* → IR (параграфы, заголовки, списки, цитаты, ссылки, медиа-блоки, таблицы как текст) и сделать его частью MVP, а не запасным вариантом. held оставить только для неизвестных типов блоков.
- **🔴 критично.** Сохранность фактов держится на LLM: self_check у writer и судья. Оба недетерминированы, а writer сам себе ставит facts_preserved=true. Пересказ ссылок (retell) по сводке researcher вносит НОВЫЕ факты, которых нет в посте автора; судья не отличит их от галлюцинаций.  
  **Исправление:** Добавить детерминированный инвариант-чекер в демоне. Из исходника извлекаются числа, проценты, суммы, даты, версии моделей, имена и названия продуктов (из analysis.entities плюс регулярки), и каждый драфт проверяется на их присутствие с нормализацией: «5 млн» = «5 000 000», числительные словами. Если writer что-то выкинул, он обязан перечислить это в поле dropped_facts с причиной; иначе драфт отклоняется. Новые числа и имена, которых нет ни в исходнике, ни в manifest.summary, — ошибка. Судья работает на ДРУГОЙ модели, чем writer, и получает список инвариантов.
- **🟠 важно.** Prompt injection и подмена первоисточника. link-researcher читает недоверенные страницы и чужие TG-посты. Его краткое содержание дословно уходит writer'у, а выбранный им «первоисточник» принимается, если код говорит ok или unknown. Rule of Two формально соблюдён (researcher без записи), но содержимое атакующего попадает в автопубликацию: Threads без одобрения, MAX авто. Отравленная страница может протащить ссылку на рекламный, фишинговый или VPN-ресурс либо навязанную формулировку.  
  **Исправление:** (1) Researcher может вернуть только URL из outbound_links, которые код извлёк сам; любой другой URL отбрасывается. (2) Кандидат проходит классификацию, и unknown-домены не принимаются автоматически: нужен allowlist или кнопка автора. (3) Сводка ограничена 300 символами, проверяется стоп-словарём (VPN, реклама, erid, призывы) и передаётся writer'у как цитата с пометкой «данные, не инструкции». (4) Пост, где хоть одна ссылка решена через research, в первые 4–6 недель публикуется только после одобрения, включая Threads. (5) Judge видит, какие куски пришли из research.
- **🟠 важно.** Запуск через `claude -p --agent` опирается на недокументированное или противоречащее документации поведение. omitClaudeMd в этом режиме официально игнорируется: CLAUDE.md из cwd и родительских каталогов, а также user memory загрузятся. Предзагрузка skills: для основной сессии не описана. Конфигурация хрупкая: обновление CLI может молча поменять, что попадает в контекст, и сломать «голос».  
  **Исправление:** По умолчанию использовать «скомпилированный» режим, а не запасной: демон собирает системный промпт из agent.md и SKILL.md и передаёт его через --system-prompt-file. Неизменяемую часть отделить строкой __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__ для кэша (v2.1.275+). Плюс --tools "" --disallowedTools "mcp__*" --json-schema --no-session-persistence. Гарантировать, что в /srv и CLAUDE_CONFIG_DIR нет CLAUDE.md. Скиллы остаются обычными файлами в git и переносятся к любому вендору.
- **🟠 важно.** Переусложнение для одного поста в день. 11+ агентов, stdio MCP-сервер, три раннера (Claude CLI, Codex, OpenAI Responses), compile_prompt, OONI, itdoginfo и antifilter в policy-updater, lessons-curator, edit-patcher в буфере. Это недели работы до первого полезного результата и много точек отказа, которые не дают качества.  
  **Исправление:** См. «упрощения»: 2–3 LLM-вызова на пост, валидатор в демоне вместо MCP, один запасной раннер (API-ключ), статичная таблица доменов в YAML, перегенерация вместо патчера в буфере, ручное одобрение правок скиллов вместо куратора.
- **🟠 важно.** Пиковая нагрузка на правках: каждое edited_channel_post создаёт версию и запускает пересчёт. По документации Bot API, edited_channel_post может приходить при изменении полей, которые бот не использует. Без сравнения хэша это лишние Opus-прогоны и путаница в превью: приходит новая версия черновиков, хотя текст не менялся.  
  **Исправление:** Перед созданием post_version сравнивать content_hash по text, entities, rich_message и media file_unique_id. Одинаковые события игнорировать. Не делать черновики в T+2: генерировать их один раз после 10 минут тишины или в T+40, что наступит раньше. Если правка пришла после превью, перегенерировать целиком (1 пост в день — это дёшево); edit-patcher использовать только для правок после публикации.
- **🟠 важно.** Нет юридического слоя для RU-сетей кроме рекламы и VPN. Упоминание иноагентов, нежелательных и экстремистских организаций (кроме Meta), а также их материалов в RU-публичном пространстве требует маркировки или чревато штрафами. Применимость к блогерам и самозанятым надо уточнить [низкая уверенность]. LLM этого не знает надёжно.  
  **Исправление:** Код сверяет analysis.entities с локальной копией реестров Минюста (иноагенты, нежелательные) и перечнем экстремистских организаций. Совпадение даёт held в RU-сетях и вопрос автору. Обновлять реестры раз в неделю. Не выдавать это за юридическую гарантию.
- **🟠 важно.** Утверждение «у приватного MAX-канала url=null», а отсюда требование сделать канал публичным, выдано за факт. Документация говорит только про диалоги и группы. Из-за этого решения автору придётся раскрыть ФИО самозанятого в профиле канала.  
  **Исправление:** В фазе 0 проверить на приватном канале, что возвращает POST /messages, и есть ли в клиенте MAX «ссылка на пост» в приватном канале. Только после этого задавать автору вопрос про публичность. Если ссылок нет, в отчёте давать «id сообщения плюс ссылку-приглашение в канал».
- **🟡 мелочь.** VK Клипы: дизайн исходит из того, что официального API нет, и сразу закладывает браузерную автоматизацию (хрупко, серая зона). При этом shortVideo.create существует и использовался в 2025 году.  
  **Исправление:** В фазе 3 сначала проверить shortVideo.create с user-токеном (право video) и выяснить ограничения, включая выключенные комментарии. Браузер — только если API недоступен.
- **🟡 мелочь.** MAX: CTA «вопрос в комментариях» и логика «если комментарии включены». Нативных комментариев в каналах MAX на 02.2026 не было, writer будет генерировать бессмысленные призывы.  
  **Исправление:** В net-max жёстко запретить призывы к комментариям. Если автор подключит бот-обсуждение, использовать его ссылку как entity_equivalent и кнопку «Обсудить».
- **🟠 важно.** Нет конвейера медиа-конвертации. В TG видео до 2 ГБ и любого кодека, в MAX ≤250 МБ, у Threads, FB и IG свои лимиты по длительности, кодеку и соотношению сторон. Картинки в WebP или HEIC, документы. Сбой проявится только на «видео + текст».  
  **Исправление:** Отдельный модуль media/transcode (ffmpeg) с профилями под каждую сеть и предварительной проверкой лимитов. Если видео не влезает, публиковать без видео с пометкой в отчёте или ставить held. Тесты на реальных видеопостах автора в фазе 0.
- **🟡 мелочь.** IR в Markdown-подмножестве (`_курсив_`, `__подчёркнутый__`). Подчёркивания в именах, никах и @mentions ломают разметку. LLM путает Markdown-варианты и экранирование, после рендера в HTML для MAX ломается баланс тегов.  
  **Исправление:** Сделать IR на простых тегах (<b>, <i>, <u>, <s>, <code>, <blockquote>, <a ref="L1">). Модели лучше их сохраняют, а код валидирует их как XML. Рендереры под сети работают от того же дерева.
- **🟠 важно.** Нет регрессионного прогона при изменении скиллов. Lessons-curator и ручные правки могут молча ухудшить другие типы постов; «понимание как у автора» деградирует незаметно.  
  **Исправление:** Golden-набор из 20–30 прошлых постов с утверждёнными адаптациями. При любом изменении скиллов, модели или версии CLI прогонять набор, инвариант-чекер и judge и показывать автору diff проблемных мест до коммита.
- **🟡 мелочь.** Статусы held (подозрение на рекламу, VPN, research, валидатор) не имеют таймаута. Если автор не ответил, пост висит вечно, а очередь зависимых постов (ссылки на свой пост) копится.  
  **Исправление:** TTL для held, например 24 часа: потом skipped с записью в недельный отчёт. Напоминание через 3 часа. Зависимые задачи после TTL переходят на retell.
- **🟡 мелочь.** Обозначенные как основные провайдеры фазы 3 (gpt-image-2.5-flare, Nano Banana 2.1, Gemini 3.8 Flash TTS, Lyria 3 Clip) частично в early access или не проверены. Тир-цены и выбор «основного» основаны на маркетинге и агрегаторах.  
  **Исправление:** Фазу 3 начинать с тира A без генерации изображений. Провайдеров выбирать на старте фазы 3 по живым ценам и слепому тесту. В документе пометить их как гипотезы.
- **🟡 мелочь.** Порядок и тайминг публикаций не учитывают время суток. Пост, написанный ночью по Португалии, уйдёт в MAX и VK в неудобное для российской аудитории время (+2–3 часа к Лиссабону).  
  **Исправление:** Опциональные окна публикации для каждой сети, например MAX и VK 08:00–23:00 МСК; вне окна — перенос на начало окна. Решает автор.

### 13.4 Чего не хватает

- Парсер Message.rich_message (Bot API 10.1–10.3) → IR и тест в фазе 0 на посте из визуального редактора TG.
- Детерминированный чекер фактов-инвариантов (числа, даты, суммы, имена, названия продуктов) с полем dropped_facts у writer и запретом новых чисел и имён.
- Модуль транскодирования медиа под лимиты каждой сети (ffmpeg-профили, проверка размера, длительности и кодека, конвертация WebP/HEIC).
- Сравнение content_hash до создания post_version, чтобы ложные edited_channel_post не запускали перегенерацию.
- Проверка упоминаний по реестрам иноагентов, нежелательных и экстремистских организаций для RU-сетей (held + вопрос автору).
- Golden-набор и регрессионный прогон при изменении скиллов, модели или версии CLI.
- TTL и напоминания для held-постов; окна публикации по времени для RU-сетей.
- Фильтр собственного «рилс»-видеопоста: видео, опубликованное ботом в TG, не должно снова уходить в кросспостинг (bot_sent_messages есть, но надо явно описать исключение из конвейера и проверить, приходит ли такой channel_post).
- Проверка изображений поста (vision или OCR) на t.me-ссылки, QR-коды, логотипы Meta и упоминания VPN в RU-сетях — текст в картинке не проходит через фильтры.
- Явный kill switch и «теневой режим» для каждой сети командой из TG; в дизайне они есть частично (/pause), но без глобального «стоп всё до ручного снятия».
- Фаза 0: тест Message.url на приватном MAX-канале и тест shortVideo.create для VK до решения о браузерной автоматизации.

### 13.5 Упрощения для MVP (принять)

- Заменить связку «post-analyst + 4–5 writer-агентов» одним вызовом «редактор» (Opus): анализ и черновики всех включённых сетей в одном JSON. Общее понимание поста гарантировано, факты согласованы между сетями, вызовов 1 вместо 5–6. Если черновик одной сети не прошёл валидатор, перегенерировать только её с ошибками в контексте.
- Вызов «судья» на другой модели (Sonnet или GPT) с детерминированными инвариантами на входе. Итого 2–3 LLM-вызова на пост.
- Убрать MCP-сервер из MVP. Валидатор живёт в демоне, при ошибке тот же вызов повторяется с ошибками (до 2 раз). Примеры (get_examples) демон кладёт во входной JSON. Остаётся один вызов `claude -p --system-prompt-file ... --tools "" --disallowedTools "mcp__*" --json-schema`, без агентов, skills-магии и проверок совместимости флагов.
- Скиллы оставить обычными Markdown-файлами в git (голос, сети, политика ссылок, примеры). Демон склеивает их в системный промпт; к другому вендору они переносятся без Codex-раннера.
- Один запасной раннер вместо двух: прямой API (OpenAI или Anthropic) с той же склейкой промпта и той же схемой.
- Политику доменов в фазах 1–2 держать в статичном YAML (~100 доменов: TG, Meta, X, LinkedIn, YouTube, сервисы, недоступные в РФ, ok_foreign) плюс overrides автора. Неизвестный домен в RU-сетях → retell и пометка в превью. OONI, itdoginfo и antifilter не нужны; заодно не придётся зависеть от списков сообществ обхода блокировок.
- link-researcher отложить в фазу 2. В MVP чужие TG-посты и Meta-ссылки в RU-сетях получают retell + attr, а автор в превью может одной кнопкой вставить свой URL первоисточника, который становится примером для будущего.
- Edit-patcher в буфере не нужен: черновики генерируются один раз после 10 минут тишины или в T+40, правка после превью → полная перегенерация. Патчер нужен только для правок после публикации, и то лишь для MAX, VK и FB.
- Lessons-curator заменить простым механизмом: исправления автора автоматически становятся примерами (top-k по типу поста во входном JSON), а правило в скилл автор добавляет командой /rule <текст>. Куратор — фаза 3+.
- Детекция удаления: оставить только forwardMessage в служебный канал. Ветку с copyMessage и has_protected_content заменить вопросом автору (включена ли защита контента; скорее всего нет).
- Рилсы фазы 3: только тир A (kinetic-типографика, скриншоты, TTS) и вариант TG A+C (вертикальный sendVideo и полуавтоматическая Story). MTProto-юзербот, ИИ-клипы и VK-браузер — только по явному запросу.

### 13.6 Дополнительные вопросы от ревьюера

1. **Пишете ли вы посты в новом визуальном редакторе Telegram (длинные посты и статьи с блоками, таблицами, заголовками) или в обычном поле сообщения?** — Посты из редактора приходят боту в новом формате rich_message. Если вы им пользуетесь, его разбор нужен в MVP, а не «потом».
2. **Что для вас «рилсы в Telegram»: Stories канала (вертикальные, исчезают, в шапке канала), отдельный вертикальный видеопост в ленте канала или и то и другое? Есть ли у вас Telegram Premium, открыты ли у канала Stories (бусты)?** — Бот не может публиковать Stories в канал. Stories — это ручной шаг или отдельный пользовательский аккаунт (риск), видеопост делается полностью автоматически. От ответа зависит весь блок фазы 3.
3. **Можно ли публиковать в Threads и MAX без вашего одобрения посты, где система сама заменила ссылку на найденный в интернете «первоисточник»? Или такие замены всегда должны проходить через вашу кнопку?** — Это главный вектор ошибок и манипуляций через чужие страницы. Ответ определяет, нужен ли researcher в MVP и бывает ли автопубликация с research.
4. **Можно ли в постах для MAX и VK вообще упоминать Telegram словами (например, «у меня в телеграм-канале»), или любые отсылки к Telegram нужно убирать или переписывать?** — От этого зависят правила writer'а и валидатора для RU-сетей: заменять только ссылки или ещё и упоминания.
5. **На каком языке Facebook-страница и Threads: русский, английский или оба?** — Английский — это перевод и культурная адаптация, отдельные примеры и другой судья. Объём работы над «голосом» вырастает вдвое.
6. **Нужно ли предпросмотр-одобрение каждого поста первые недели, и успеваете ли вы реагировать в течение часа? Или достаточно отчёта после публикации, а одобрение только для спорных случаев?** — Ответ определяет, когда генерировать черновики (T+5 или T+40), нужен ли edit-patcher и сколько автопубликации будет на старте.
7. **Упоминаете ли вы в постах людей или организации, которые в РФ признаны иноагентами, нежелательными или экстремистскими (кроме Meta)? Как поступать с такими постами в MAX и VK: пропускать, маркировать, спрашивать вас?** — Без этого правила RU-сети несут юридический риск, а реализация (проверка по реестрам и маркировка) заметно меняет конвейер.
8. **VK: это сообщество или личная страница? Есть ли у вас старое Standalone-приложение VK с правами wall и video, и допустима ли публикация через браузер под вашим логином на сервере?** — От этого зависит, будет ли публикация в VK через API или через хрупкую браузерную автоматизацию. Это определяет сроки фазы 2.
9. **Есть ли время суток, когда публиковать в MAX и VK нельзя (например, ночью по Москве)?** — Если ограничение есть, нужны окна публикации и перенос, а правило «ровно через час» перестаёт быть жёстким.
